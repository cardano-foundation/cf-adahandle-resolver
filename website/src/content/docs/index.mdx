## Why another resolver?

Kora Labs already runs the excellent [api.handle.me](https://github.com/koralabs/api.handle.me).
This resolver is for teams that want to **own the data path**: run it next to your own infrastructure,
read it in plain Java and extend it.

<CardGrid stagger>
	<Card title="Talks to a node, nothing else" icon="rocket">
		Syncs blocks directly from a Cardano relay or a local node through Yaci Store. No Ogmios,
		no Blockfrost, no db-sync.
	</Card>
	<Card title="Tiny footprint" icon="seti:db">
		It stores two small tables, the current handles and their history, and no UTxOs. Run it on
		embedded H2 for a single box, or on PostgreSQL for production.
	</Card>
	<Card title="Every kind of handle" icon="star">
		Both ADA Handle policies, including DeMi; legacy and CIP-68 handles; NFT and virtual sub-handles.
		Burned handles stop resolving, just as on handle.me.
	</Card>
	<Card title="Checked against handle.me" icon="approve-check">
		The rules follow Kora Labs' implementation. A regression suite syncs mainnet from scratch and
		compares the result with their API.
	</Card>
	<Card title="Fork-safe" icon="random">
		Every ownership change and burn is kept in a history table keyed by slot, so chain rollbacks
		restore the previous state instead of leaving stale data behind.
	</Card>
	<Card title="Plain Java 25" icon="seti:java">
		Spring Boot and the Yaci Store modular indexer. It is a compact, readable reference for building your
		own scoped indexer.
	</Card>
</CardGrid>

## Run it in one line

```sh
docker run -p 9095:9095 -e JAVA_TOOL_OPTIONS=-Xmx4g cardanofoundation/adahandle-resolver:latest
```

Once the sync has caught up, you can resolve handles:

```sh
curl http://localhost:9095/api/v1/addresses/by-ada-handle/\$alice
```
