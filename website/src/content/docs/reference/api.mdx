All endpoints are `GET`, return JSON, and live under `/api/v1`. The server listens on port `9095`
by default. Any origin can call them (CORS).

<Aside type="tip" title="OpenAPI">
The resolver publishes its OpenAPI 3 spec at **`/apidocs`** and serves Swagger UI at
**`/swagger-ui.html`**. The [OpenAPI section](../../api/) of this site is generated from the same
spec, and documents only the resolver's own endpoints, below.
</Aside>

## Resolve a handle to addresses

<Badge text="GET" variant="success" /> `/api/v1/addresses/by-ada-handle/{adaHandle}`

Returns the addresses that currently hold the handle.

| Parameter   | In   | Description                                          |
| ----------- | ---- | ---------------------------------------------------- |
| `adaHandle` | path | Handle name, with or without the leading `$`; a sub-handle as `sub@root` |

```sh
curl 'http://localhost:9095/api/v1/addresses/by-ada-handle/$alice'
```

**200 OK**

```json
{
  "stakeAddress": "stake1u8…",
  "paymentAddress": "addr1q9…"
}
```

`stakeAddress` is `null` when the handle sits at an address without a stake part, such as an
enterprise or script address. A virtual sub-handle returns the address in its datum, not the script
address that holds its token.

**404 Not Found**: the handle doesn't exist, has been burned, or hasn't been indexed yet.

## Handles held by a stake address

<Badge text="GET" variant="success" /> `/api/v1/ada-handles/by-stake-address/{stakeAddress}`

Lists every handle held by any payment address that delegates to this stake key.

```sh
curl http://localhost:9095/api/v1/ada-handles/by-stake-address/stake1u8…
```

**200 OK**

```json
["alice", "sub@alice"]
```

## Handles at a payment address

<Badge text="GET" variant="success" /> `/api/v1/ada-handles/by-payment-address/{paymentAddress}`

Lists the handles held at exactly this address, including virtual sub-handles whose datum points to it.

```sh
curl http://localhost:9095/api/v1/ada-handles/by-payment-address/addr1q9…
```

**200 OK**

```json
["alice"]
```

<Aside>
Both list endpoints return `200` with an empty array `[]` when the address holds no handles. Handles in
responses never include the `$` prefix.
</Aside>

## Matching rules

- Handle lookups are exact, apart from the optional leading `$`. ADA Handles are lowercase on
  chain, so send them in lowercase.
- Burned handles are gone: they return `404` and don't appear in the list endpoints.
- Addresses must be bech32 (`addr1…`, `stake1…`, or the `_test` variants on testnets).
- Results show the **current** owner, as of the last block the indexer has processed. During the
  initial sync, recently transferred handles may still show an older owner.

## Sync status

Yaci Store, which the resolver is built on, adds endpoints of its own. They are for operators, not for
looking up handles, so they are left out of the OpenAPI spec, but they work as usual:

- `/api/v1/sync/status`: the block the indexer has reached, the chain tip, and whether it has caught up.
- `/api/v1/genesis`: the network's genesis parameters.

```sh
curl http://localhost:9095/api/v1/sync/status
```

```json
{"block":6638041,"slot":48154092,"era":"Alonzo","network_block":14157046,"lag_blocks":7519005,"synced":false, …}
```

`synced` turns `true` and `lag_blocks` drops to about `0` once the resolver follows the tip. Ignore
`sync_percentage`: it counts from the start of the chain, not from the first ADA Handle block where the resolver
starts, so it reads high from the beginning.
