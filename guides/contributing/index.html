Design decisions

Section titled “Design decisions”

The rules the resolver follows, and why, are recorded as architecture decision records (ADRs) in docs/adr. ADR 2, the resolution rules taken from Kora Labs’ implementation, is the closest thing to a specification. Read the ADRs before changing how handles are indexed. A change to one of those decisions comes with a new ADR.

Guidelines shared by the Cardano Foundation’s Java services, such as native image builds, testing, observability and releases, are kept in the Cardano Foundation’s internal cf-java-nfrs repository and are not repeated in the ADRs.

ADA Handle tokens and datums

Section titled “ADA Handle tokens and datums”

ADA Handle tokens and datums describes every kind of handle: its tokens, its CIP-25 metadata or CIP-68 datum, decoded field by field from real mainnet data, and how a virtual sub-handle’s datum becomes the address the API returns. How indexing works gives the shorter version.

Pull requests and releases

Section titled “Pull requests and releases”
  • Discuss a change in an issue first, then open a pull request against develop. See CONTRIBUTING.md.
  • Commit messages and pull request titles follow Conventional Commits: release-please builds the changelog from them.
  • develop is promoted to main for a release. A release candidate (X.Y.Z-rcN) or a final release (X.Y.Z) gets its version from a Release-As: footer on a commit, e.g. Release-As: 1.1.0-rc1; release-please then opens the release pull request. Merging it tags the release and publishes the Docker images.
