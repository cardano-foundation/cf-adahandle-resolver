Deployment

Container image

Section titled “Container image”

Every release is published to Docker Hub as cardanofoundation/adahandle-resolver, tagged with the release version and latest. Pin a version in production. The image is built for x86-64 (amd64) and runs on older CPUs too, including VMs with a generic CPU model.

A release can be preceded by release candidates for testing, versioned X.Y.Z-rcN and published under that tag (-native for the native image). latest moves only with final releases, never to a release candidate.

The JVM image is built on Eclipse Temurin 25 on Ubuntu 26.04 LTS (eclipse-temurin:25-jre-resolute), taking the latest Java 25 and Ubuntu updates at each release. The native image embeds the same Java trust store (its root certificates). The build fails if that trust store still contains the roots that signed the compromised eMudhra intermediate CAs, removed in Temurin 25.0.5 (Adoptium’s notice).

Native image (experimental)

Section titled “Native image (experimental)”

Each release is also published as a GraalVM native image, tagged <version>-native, next to the JVM image <version>. It starts in under two seconds, against about nine for the JVM image, and used about 1.1 GB of memory throughout a mainnet sync. Configure it with the same environment variables; JVM flags go on the command line:

There is no moving native tag such as latest: pick the release you run. Like the JVM image, the native image is built for x86-64 (amd64) only.

The native image is also built and smoke-tested every week, without publishing anything, so a change that breaks it under GraalVM shows up before the next release.

To build it yourself, run docker build -f Dockerfile.native -t adahandle-resolver:native .. GraalVM’s compiler needs a lot of memory: a build on an 8-core host took 28 minutes and used up to 17.5 GB of memory. The resulting executable is about 430 MB.

It’s built with Oracle GraalVM. The GraalVM parts compiled into the executable are covered by the GraalVM Free Terms and Conditions, which allow free use, including in production and hosted services, and free redistribution, but not redistribution for a fee. The image includes Oracle’s license and notices in /licenses/graalvm. The resolver’s own code is MIT licensed, and the JVM image contains no GraalVM.

Docker Compose

Section titled “Docker Compose”

The repository’s docker-compose.yml runs PostgreSQL 17 and the API, each with a health check (for the API, see Monitoring). All settings come from .env. Copy .env.example to get started. The Quickstart walks through it.

Both services use restart: unless-stopped, so the stack comes back after a crash and after a host reboot. After upgrading, run docker compose up -d once so existing containers pick up the policy.

Kubernetes with Helm

Section titled “Kubernetes with Helm”

The chart lives in deploy/adahandle-resolver. It creates a Deployment, a Service on port 9095, and either an Ingress (on by default) or a Gateway API HTTPRoute. By default it deploys the resolver release the chart belongs to (its appVersion); set image.tag to run another one. You can choose between three storage setups:

  • Embedded H2
  • Zalando operator
  • Your own PostgreSQL

This is the default (values.yaml). H2 stores its data on a 20 Gi PersistentVolumeClaim mounted at /data.

This option provisions a PostgreSQL cluster through an existing Zalando Postgres operator installation.

Any PostgreSQL you run yourself, such as a managed service. The connection details come from a secret you create first, in the release namespace:

A synced mainnet database is about 5 GB and grows with the chain.

Useful values

Section titled “Useful values”
Value Purpose Default
image.tag Resolver image version the chart’s appVersion
springProfiles Same as SPRING_ACTIVE_PROFILES mainnet,h2
javaToolOptions JVM flags, including the heap -Xmx4g …
resources Pod requests and limits. Keep the memory limit about 0.5 Gi above -Xmx, or the pod is OOMKilled. none
domain, ingress.* Ingress host and extra domains example.com, enabled
httpRoute.* Gateway API HTTPRoute instead of the Ingress: enabled, hosts, parentRef (the Gateway). It routes /api/v1 and /apidocs. disabled
serviceAccount.name Existing ServiceAccount to run under (the chart doesn’t create one) namespace default
imagePullSecrets ["regcred"] or [{name: regcred}] []
startupProbe.* Startup probe timing 60s delay, 20s period

The liveness, readiness and startup probes use the health groups described in Monitoring. A new pod is not ready until its sync reaches the tip, about 6.5 hours on mainnet.

Memory limit vs. heap

Keep resources.limits.memory above the -Xmx in javaToolOptions, roughly -Xmx plus 0.5 Gi. Otherwise Kubernetes kills the pod (OOMKilled) as soon as the heap grows during the mainnet sync.
